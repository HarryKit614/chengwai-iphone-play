# 《廿四道·城外》制作 skill（2026-09-25）

给后面每一步用。旧的 `lysk-romantic-design` 里，「真竖屏」和「不做换装、不做战斗」作废。关系顺序、他在场、节点表，继续用。

## 一句话

心动来自关系信息的顺序，和他一直在场。道途、渡灵、行职、职反、并肩战斗、衣冠，都是这两件事的做法。

## 什么时候用

做主界面、行职、衣冠、符箓、战斗遭遇、出图和验收时先读这份。用户要看某一步的成果时，只交这一步的完成稿，并写明过没过下面的门。

## 六条（执行时按这个顺序判断）

1. **关系顺序。** 先写玩家此刻已经知道什么，再决定允许什么亲密、什么并肩。初识只做功能性接触。信任之后才有长对视和低强度依赖。战斗里的挡伤、关心，要等关系到了再出现。
2. **他在场。** 主界面是 16:9 舞台，人在画面里。功能放底栏：行职录、衣冠、行囊、天市、署务，外加在场、主线、共处、图鉴。
3. **精致度。** 半写实厚涂，靠近恋与深空。饱和度和明暗要够。人和场景一次画进同一张 1280×720，光是同一套。顾山只认 `images/art/gu_face_lock_user.jpg`：窄脸、眉眼沉静、黑色碎发、肩宽、脖子长、约一米九、表情温和，不咧嘴笑，不蹲，不弓背。
4. **衣冠。** 玩家看到的永远是完整的人。单独一层也必须是完整部件：裤子从腰连到靴，不能在大腿中段断开。头发可以分开换。秃头底、填洞、程序画的光滑皮带，是工序，不是成果，不发给用户。
5. **行职。** 日常、道途、主线、共处。漏做不惩罚。符箓给男主加属性，用来卡门槛。免费玩家照常做能过。付费只是早一点。数值以 `docs/FU_ATTRIBUTE_BALANCE_DRAFT.md` 为准。
6. **战斗即浪漫。** 战斗是并肩，不是另一款动作游戏。网页 Demo 做成横屏遭遇：属性门槛、开战前能看剧情、不够时告诉他还差哪一项、哪条行职能补。不做 3D 动作战，也不做抽卡。

## 出图门（每张图发出去之前自己过）

没过的图不发。过了要在交付里写一句「过了哪几条」。

- 脸并排对过基准图：脸宽、眉眼、碎发、脖子长度没有漂。
- 衣服是完整的：该有的腰、袖、靴都在，没有洞，没有半截模型。
- 人和背景是一张画，不是抠图贴上去。
- 皮带、布、皮靴能看出材质，不是光滑塑料。
- 缩小到手机宽度，还能认出是谁、穿着什么。
- 画面里没有工序层（秃头、洋红边、棋盘格、检查用色块）。

## 衣冠怎么做（猎服以及后面六套）

1. 先有一套定稿 CG（人、衣服、场景在一起）。七套已经有了，在 `images/art/outfits/cg/final/`。
2. 分层只为了在衣冠页替换。每一层单独拿出来也要能看，不能靠别的层补洞。
3. 弓、箭袋垫在身体后面，不穿模。
4. 交给用户的检查，只给完成状态：例如「单穿下装的完整的人」「全装的完整的人」。不给秃头工序图。
5. 用户点头之后，才接进衣冠页，五处版本号一起改，再截手机尺寸。

## 工具

- 仓颉：用来把方法收成步骤。本地在归档 `project/other/cangjie-skill`。
- 审美验收：出图门上面那六条。有争议时按「有没有接缝、光是否统一、缩小后还认不认得出」打回。
- 出图：以基准图和该套定稿 CG 为参考，重画完成稿。禁止用填色、inpainting 把缺的裤腰或皮带补上冒充完成稿。
- 不用恋与深空的扒包和搬运素材。
